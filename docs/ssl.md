# Certificates

ngx doesn't talk to Let's Encrypt itself; it drives **certbot**. Install it first:

| Distribution | Package |
|---|---|
| Debian / Ubuntu | `apt install certbot` (plus `python3-certbot-nginx` for sites not created by ngx) |
| Arch | `pacman -S certbot` (plus `certbot-nginx`) |
| Fedora / RHEL | `dnf install certbot` (plus `python3-certbot-nginx`) |

Then make sure something runs `certbot renew` regularly, usually the systemd timer: `systemctl enable --now certbot.timer`.
On Arch, certbot ships no timer; create one or a cron job (see [troubleshooting](troubleshooting.md#no-renewal-scheduler)).

## Getting a certificate

- **New site**: choose *Let's Encrypt* in `ngx add` (this is the default with `-y`).
- **Existing site**: `ngx cert issue <site>`, or `ngx edit <site>` and pick *Let's Encrypt*.

Before you start:

- The domain (and every alias) must resolve to this server, both `A` and, if you have IPv6, `AAAA` records.
- Port **80** must be reachable from the internet. Let's Encrypt checks it even if the site will use 443.
- For tests, add `--staging` so you don't hit Let's Encrypt's rate limits (5 failed attempts per hour, 50 certificates per domain per week).

### How ngx-created sites are validated

Every config generated by ngx contains, on its port 80 server:

```nginx
location ^~ /.well-known/acme-challenge/ {
    root /var/lib/ngx/acme;
    default_type text/plain;
}
```

certbot runs in webroot mode (`certbot certonly --webroot -w /var/lib/ngx/acme`) and drops the challenge file there.
This works the same for first issuance and every renewal, and doesn't need certbot to edit nginx files. The
certificate is named after the domain (`--cert-name <domain>`) and stored in `/etc/letsencrypt/live/<domain>/`.

### Sites you wrote yourself

`ngx cert issue` uses certbot's nginx plugin (`certbot --nginx --redirect`), which edits your config to add the
certificate and an HTTP→HTTPS redirect. Alternatively, `ngx edit <site>` converts the site to an ngx-generated
config (showing you the diff first) and then uses the webroot method.

## Auto or manual?

The `RENEW` column says whether the certificate will renew **without you doing anything**. It is `auto` only if all of
these hold:

1. The certificate is a certbot certificate (its path is under `/etc/letsencrypt/live/`).
2. certbot has a renewal config for it (`/etc/letsencrypt/renewal/<name>.conf`).
3. That config doesn't have `autorenew = False`.
4. It doesn't use the `manual` authenticator without a `manual_auth_hook` (manual DNS challenges can't renew unattended).
5. Something runs certbot: an active `certbot.timer`, `snap.certbot.renew.timer` or `certbot-renew.timer`, a
   `/etc/cron.d/certbot` or `/etc/cron.daily/certbot` file, or a `certbot` line in root's crontab.

Otherwise it's `manual`, and `ngx show` tells you which point failed (`autorenew disabled`, `no certbot timer or cron
job`, `not issued by certbot`…).

Turn auto-renewal on or off per certificate with `ngx cert auto <site> on|off`.

## Expiry warnings

- `valid until <date> ⚠`, in yellow: fewer than 30 days left. certbot normally renews at 30 days, so an `auto`
  certificate showing this means renewals are failing. Run `sudo certbot renew --dry-run` to see why.
- `expired <date>`, in red: browsers refuse the site. Run `ngx cert renew <site> --force`, or `ngx cert issue <site>`
  if the certificate needs new names.

`ngx show` also lists **Not covered** names: names the site answers to that the certificate doesn't include.
Browsers show a certificate error for those. Fix it with `ngx cert issue <site>` (certbot adds the missing names), or
by removing the alias with `ngx edit`.

## Your own certificates

Choose *existing certificate* in `ngx add` / `ngx edit` (or `--ssl existing --cert <fullchain.pem> --key <key.pem>`).
ngx reads the expiry and names from the file, but can't renew it; `RENEW` shows `manual · not issued by certbot`.
Replace the files before they expire and run `ngx reload`.

## Removing certificates

`ngx rm <site> --delete-cert` removes the site and runs `certbot delete` for its certificate. Removing a site without
`--delete-cert` keeps the certificate, and certbot keeps renewing it.
